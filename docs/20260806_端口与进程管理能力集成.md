# 端口与进程管理能力集成

> **归档说明**: 本文原是工作目录下的过程文件（位于被 gitignore 的 `.ai-ctx/`），现按原貌归档到 `docs/` 以保留决策依据。正文中关于路径、工作区状态、以及「本文件不进入提交」一类的表述反映的是当时情形，不再描述当前仓库；本机绝对路径已替换为 `<骨架仓库>` / `<工作区>` 等占位符。

- 方案状态: 已完成
- 任务规模: 长

把 `hassansaadfr/vscode-port-cleaner` 的能力集成进 `editor-console-toolkit`, 并补齐两项上游没有的能力: 展示端口对应进程的源头/启动信息用于区分来源, 以及批量终止进程。

## 1. 目标与验收标准

1. 活动栏出现 PORTS 视图, **以进程为根节点**列出本机监听端口, 每行直接可见进程名, 该进程聚合的全部端口, 以及"本工作区"标记; 展开后可见 PID, PPID, 用户, 运行时长, 工作目录, 完整命令行, 全部监听地址。
2. 视图项支持原生 checkbox 多选, 一次操作批量终止所选进程; 勾选数与实际终止的进程数永远一致。
3. 终止策略为 SIGTERM → 超时升级 SIGKILL, 仅目标进程, 不触碰进程树。
4. 编辑器自身及其祖先进程置灰且不可勾选, 任何路径都不会被终止; 其他用户的进程照常列出但标记为不可终止。
5. 视图不可见时零刷新活动; 刷新间隔可配置, 设为 `0` 时完全手动。
6. 现有 3 个 console 命令的 ID, 行为与 `editorConsoleToolkit.prefix` 配置完全不变; `dependencies` 仍为空; 无 `activationEvents`。
7. `npm run typecheck` / `npx vitest run` / `node scripts/check.mjs` / `npm run build` / `npm run package` 全部通过。
8. `docs/` 与 `README.md` 中不再存在与实现矛盾的表述; `CHANGELOG.md` 存在 `## 0.0.2` 小节且 `node scripts/changelog-section.mjs 0.0.2` 输出非空。

## 4. 设计决策与理由

### 4.1 决策表

| 决策 | 选定 | 理由 / 否决原因 |
| --- | --- | --- |
| UI 形态 | TreeView 侧边栏, 原生 `checkboxState` 多选 | 用户拍板; 已核实 API 在 1.101 可用。否决 QuickPick 方案 (无常驻可视化) |
| 门禁改造粒度 | 按目录白名单: `GLOBAL_FORBIDDEN` 全目录生效, `CONSOLE_ONLY_FORBIDDEN` 只对 `src/` 下非 `src/ports/` 的文件生效; `FORBIDDEN_MANIFEST_KEYS` 清空为 `[]`; **保留并行改动新增的第 7 项快捷键契约检查不动** | 用户拍板; 保留 console 部分的零后台开销承诺, 避免日后无意给 console 命令加监听器。否决整体删除禁止项与废除 `check-extra.mjs` |
| 树的根节点单位 | **以进程为根**, 端口聚合到该行 | 用户拍板; 终止的单位本就是进程, 勾选数与被终止进程数永远一致。否决"以端口为根 + 终止时按 PID 去重" (会出现勾 2 项只杀 1 个进程的误导) |
| 刷新策略 | 仅 `TreeView.visible` 为真时 `setInterval`, 默认 5000ms, 配置 `0` 关闭; 手动刷新与终止后立即重扫 | 用户拍板; 最大程度保留原有零后台开销承诺。否决上游的无条件 3s 轮询 |
| 终止策略 | `SIGTERM` → 轮询存活至 `killTimeout` → `SIGKILL`; 仅目标进程 | 用户拍板; 给 dev server 清理 socket 与临时文件的机会。否决直接 SIGKILL 与终止进程树 |
| 发现范围 | 默认只列 TCP LISTEN, `includeUdp` 可开启 UDP | 用户拍板 |
| 系统项过滤 | 默认隐藏, `hideSystemProcesses` 可关闭 | 用户拍板 |
| 系统项判定方式 | **规则化**: 可执行路径位于 `/System`, `/usr/libexec`, `/usr/sbin`, `/sbin`, `C:\Windows` 前缀, **或**其全部 listener 端口都 `<= systemPortMax`; 任一端口超阈值即显示 | 否决移植上游名单: 不复制代码, 且名单会持续腐化。"任一端口超阈值即显示"防止占用 8080 的系统进程被静默藏掉 |
| 编辑器自保护 | 启动时从 `process.pid` 沿 ppid 链上溯得祖先 PID 集合, 集合内的项不设 `checkboxState` 且无右键终止菜单 | 已实测链路可达编辑器主进程; 不依赖进程名匹配, 对 VS Code / Cursor / Windsurf 等衍生版一律有效。否决按进程名黑名单 |
| 其他用户进程 | 照常列出, 标记 `blockedReason: 'other-user'` 且不可勾选 | 用户明确未勾选"排除非当前用户的进程"; 列出有助于诊断"端口被谁占了", 但扩展无法提权故不可终止 |
| 子进程调用出口 | 全部经 `src/ports/scan/exec.ts` 单一接缝, 用 `execFile` 传 argv 数组不经 shell | 解析器保持纯函数可进 vitest; argv 数组消除上游把 PID 拼进 shell 字符串的注入面 (`macScanner.ts:38`) |
| 退出码处理 | 退出码非 0 **不**视为失败; 仅当 `stdout` 为空**且** `stderr` 非空时抛错 | 已实测 `lsof` 无匹配即返回 1 |
| macOS 采集 | 3 次固定调用: `lsof -nP -iTCP -sTCP:LISTEN [-iUDP] -FpcnLRP` → `ps -ww -o pid=,etime=,args= -p <批量>` → `lsof -a -p <批量> -d cwd -Fpn` | 全部已实测可用, 总耗时约 20ms; `R` 字段直接给 ppid, 无需额外调用。否决上游 N+1 次 `ps -p` |
| Linux 采集 | `ss -tlnpH` 与 `ss -ulnpH` **逐协议**调用 (`-H` 去表头), 失败回退 `netstat -tlnp` / `netstat -ulnp`; 补 `ps -ww -o pid=,ppid=,etime=,args= -p <批量>` 与 `readlink -f /proc/<pid>/cwd` | `-H` 消除按 `slice(1)` 跳表头的脆弱性; 逐协议消除混合行列数不一致 (`linuxScanner.ts:32`); `readlink` 走 exec 接缝故 `src/` 不需要 `node:fs`, 门禁的 `readFileSync` 禁止项无需放宽 |
| Linux 非 root 缺 PID | **保留条目**, `pid` 置 `null`, `killable: false` | 否决上游整条丢弃: 用户至少应知道端口被占, 即使归属不明 |
| Windows 采集 | PowerShell `Get-NetTCPConnection -State Listen` (+ `Get-NetUDPEndpoint` 当 `includeUdp`) 与 `Get-CimInstance Win32_Process`, 均 `ConvertTo-Json -Compress`, 用 `JSON.parse` 解析 | 否决 `wmic` (已弃用) 与 CSV `split(',')` (命令行含逗号即错列)。单条结果时 PowerShell 输出对象而非数组, 需归一化 |
| PID 批量长度 | `-p` 逗号列表按 256 个 PID 分块 | 防止极端数量下超出 argv 长度上限 |
| 去重 | 先按 `pid` 聚合成 `ProcessEntry`, 组内 listener 按 `protocol + port` 合并, 全部地址保留进 tooltip | 已实测同 PID 同端口的 v4/v6 双行 |

interface ProcessEntry {
  pid: number | null;                    // Linux 非 root 时可能取不到

  user: string;

interface ScanOptions { includeUdp: boolean }

type RunCommand = (file: string, args: string[]) =>
  Promise<{ stdout: string; stderr: string; code: number }>;

type SendSignal = (pid: number, signal: NodeJS.Signals | 0) => void;

1. **`collectAncestors` 增加 `platform` 参数** —— 方案只写了"沿 ppid 链上溯", 但 Windows 上没有 `ps -o ppid=`。POSIX 走 `ps`, Windows 走 PowerShell 的 `(Get-CimInstance Win32_Process -Filter 'ProcessId=N').ParentProcessId`; 两者都只输出一个数字, 因此 `parsePpid` 通用。
2. **`annotateKillability` 在用户名缺失时不判 `other-user`** —— Windows 上 `GetOwner` 可能失败使 `user` 为空串; 若照判会把可终止的进程误标为不可终止。加了显式断言覆盖。
3. **`isInside` 同时按 `/` 与 `\` 分段** —— 方案只说"按路径分段比较", 未指定分隔符。用 `split(/[/\\]/)` 使 Windows 路径 (`C:\repo\web`) 与 POSIX 路径走同一套判定, 并各有断言。
4. **系统目录前缀增加 `/usr/lib/`** —— 方案列了 `/System`, `/usr/libexec`, `/usr/sbin`, `/sbin`, `C:\Windows`; Linux 上大量系统服务 (如 postgres 的实际可执行文件) 位于 `/usr/lib/`, 遗漏会让 Linux 侧的系统项过滤基本失效。前缀一律带尾部分隔符, 避免 `/sbin` 命中 `/sbinx`。
5. **新增 `shortenPath` 导出** —— 把工作目录的 home 前缀缩成 `~` 供 U5 展示。它复用同一个 `isInside` 分段比较, 放在别处会导致路径判定逻辑分裂成两份。
6. **`annotateKillability` 与 `applyFilters` 返回新对象** —— 不原地改写传入的条目, 并有"不修改输入数组"的断言; provider 每轮重扫都会复用上一轮的数组引用, 原地改写会让状态在轮次间渗漏。
