# 查找并终止占用端口的进程

[English](../../docs/ports.md) · **简体中文**

读完这页，你能找到占着某个本机端口的进程，把它和相似的进程区分开，并安全地终止它。前提：macOS、Linux 或 Windows，VS Code 1.101 及以上，且在本机桌面窗口中使用。

## 打开视图

点开活动栏里的端口工具箱图标。视图列出所有在本机端口上监听的进程，**每个进程一行，而不是每个端口一行**，所以勾选几行就恰好终止几个进程。下面是布局示意，实际界面用的是 VS Code 自带图标，不是这些符号。

```text
端口工具箱                                    🗑  ⧩  ⟳
  🔍 搜索                  例如 3000, node, ~/repo
  ☑ node                5173, 24678  ·  本工作区
      PID: 41802  ·  PPID: 41799  ·  sky
      运行时长: 12:33
      工作目录: ~/repo/web/apps/site
      监听于: TCP 0.0.0.0:5173  ·  TCP 127.0.0.1:24678
      命令行: node vite --host --port 5173
  ☑ node                3000  ·  本工作区
  ☐ java                8080
  🔒 Code Helper         6001  ·  编辑器自身
```

标题栏上依次是「终止已勾选的进程」（垃圾桶图标）、「切换系统进程的显示」（漏斗图标）和「刷新端口列表」（刷新图标）。端口工具箱的所有命令都没有默认快捷键。

## 区分相似的进程

`本工作区` 标记表示该进程是从你打开的某个工作区文件夹里启动的；同时有几个 `node` 在监听时，靠它认出哪个是你的。展开某一行或把鼠标悬停在上面，可以看到其余信息：

| 字段 | 含义 |
| --- | --- |
| PID、PPID | 进程 ID 与父进程 ID |
| 用户 | 进程所有者 |
| 运行时长 | 进程已经运行了多久 |
| 工作目录 | 进程的启动位置，主目录下的路径缩写为 `~` |
| 监听于 | 全部监听端点，含协议与绑定地址 |
| 命令行 | 完整命令行，不做截断 |

## 搜索列表

点击顶部的搜索行开始输入，稍停片刻列表就会收窄。可以匹配进程名、命令行、PID、工作目录和任意端口号，`5173`、`vite`、`~/repo/web` 都能搜。

- 按 Enter 保留过滤；按 Esc 恢复到打开输入框之前的过滤条件。
- 过滤生效时，搜索行显示关键词和匹配数量，旁边有一个清除按钮。

```text
端口工具箱                                    🗑  ⧩  ⟳
  🔍 搜索: 3000                已显示 7 项中的 2 项  ✕
  ☑ node                3000  ·  本工作区
  ☐ java                30001
```

过滤不会清掉勾选：过滤前勾选的进程即使被隐藏，仍会和其他勾选项一起被终止。确认对话框总会列出即将终止的全部进程。

## 终止进程

1. 勾选要停掉的行。自动刷新不会清掉勾选。
2. 点标题栏上的「终止已勾选的进程」，弹出的对话框会逐个列出将被终止的进程。
3. 确认。随后的提示会报告实际终止了几个、跳过了哪些。

只停一个进程时，把鼠标悬停在那一行上，点出现的 ✕。

每个进程都先收到正常退出请求（`SIGTERM`；Windows 上是 `taskkill`），超过 `editorConsoleToolkit.ports.killTimeout` 仍未退出才强制结束。另有四条保护：

- 不动子进程，只向那一行对应的进程发信号。
- 发信号前会重新读取命令行。如果这个 PID 已经换成了别的命令，该行会被跳过并在结果里注明。
- 编辑器自身的进程带锁形图标，没有勾选框。它们是从实时进程树推算出来的，因此换成其他兼容 VS Code 的编辑器也能认出来。
- 其他用户的进程会列出，但无法终止；插件从不提权。

## 调整刷新与过滤

视图只在可见时重新扫描，切到活动栏的其他图标计时器就停止。扫描失败时视图里只显示一行错误，不会每轮都弹通知。

| 设置 | 默认值 | 取值与含义 |
| --- | --- | --- |
| `editorConsoleToolkit.ports.refreshInterval` | `5000` | 0–600000 毫秒，视图可见时的扫描间隔；`0` 表示只手动刷新 |
| `editorConsoleToolkit.ports.killTimeout` | `3000` | 0–60000 毫秒，发出正常退出请求（`SIGTERM`）后等多久再强制结束 |
| `editorConsoleToolkit.ports.hideSystemProcesses` | `true` | 隐藏系统进程（判定见下文）；「切换系统进程的显示」会在用户设置里翻转它 |
| `editorConsoleToolkit.ports.systemPortMax` | `1024` | 0–65535，视为系统端口的最大端口号 |
| `editorConsoleToolkit.ports.includeUdp` | `false` | 除 TCP 监听外，也列出 UDP 端点 |

进程从系统目录启动，或者它监听的所有端口都不超过 `systemPortMax` 时，算作系统进程。只要有一个端口高于这个阈值就会显示出来，所以占着 `8080` 的系统进程不会被悄悄藏起来。

## 了解平台支持情况

端口信息来自系统自带的工具：macOS 用 `lsof`，Linux 用 `ss`（不可用时退回 `netstat`），Windows 用 PowerShell。**目前只在 macOS 上实机验证过**；Linux 和 Windows 的解析只有测试覆盖，发现异常请[提交 issue](https://github.com/HeavenSky/editor-console-toolkit/issues)。

系统不肯告知某个 socket 属于哪个进程时（Linux 上没有 root 权限就会这样），这一行仍会列出，端口可见，所有者标为「归属不明」，至少能让你知道端口已被占用。
