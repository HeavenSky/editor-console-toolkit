# 修复安装已损坏警告

[English](../../docs/checksums.md) · **简体中文**

读完这页，你能在改过编辑器自身的文件后消掉「安装似乎已损坏」警告，并在需要时撤销。前提是使用本机桌面窗口；在远程（SSH、WSL、容器）窗口和网页版里，命令会拒绝执行。

## 修复校验和

执行「修复校验和」，再完全重启编辑器，警告和标题栏里的 `[Unsupported]` 就会消失。

1. 在命令面板执行「校验和工具箱：修复校验和」，通知会告诉你修复了几条。
2. **完全退出编辑器再重新打开**；只重载窗口不会生效。
3. 每次升级编辑器后都要再执行一次：升级会替换 `product.json`，警告随之回来。

警告的起因是编辑器 `product.json` 里记录的校验和与磁盘上的文件对不上了。命令会重新计算 `checksums` 下列出的每个文件的 SHA-256，只写回确实有变化的条目。已不存在的文件会被跳过并在结果里注明；没有任何差异时，什么都不写。

## 磁盘上改了什么

第一次写入前，`product.json` 会被复制成同目录下的 `product.json.ect-orig.<version>`，之后的执行不会覆盖这份副本。新内容先写入同目录的临时文件，再改名覆盖 `product.json`，所以中途被打断也不会留下截断或丢失的文件。

第一次修复还会重新格式化 `product.json`，文件大约变大 4 KB；数据完全等价，逐字节一致的原件在备份里。执行任一命令时，会顺带删除其他编辑器版本留下的备份，但只删名为 `product.json.ect-orig.*` 的文件。

## 撤销修复

执行「校验和工具箱：还原校验和」，然后完全退出并重启编辑器。它先把备份写回，确认成功后才删除备份。

还原得到的是本插件第一次修复之前的状态，而不是出厂时的 `product.json`：如果此前已有别的工具改过校验和，备份里存的就是那个状态。没有备份时，只能重装编辑器；设置和插件存放在别处，重装后仍在。

## 安装目录不可写时

在 Windows 和 Linux 上，安装目录通常只有管理员能写，而插件从不提权。它会把修好的 `product.json` 存到临时目录，再在通知里给出完成剩余步骤的命令，并附带「复制命令」按钮：

```sh
sudo cp "…/product.json" "…/product.json.ect-orig.1.132.0" && sudo cp "/tmp/editor-console-toolkit/product.json" "…/product.json"
```

在有管理员权限的终端里执行它，然后完全退出并重启编辑器。Windows 上这条命令用的是 `copy /Y`，需要在以管理员身份运行的终端里执行。

## 确认支持哪些编辑器

- 适用于 VS Code 及安装布局相同的编辑器，例如 Cursor、VSCodium、Windsurf；安装目录取自正在运行的编辑器，不靠猜测。
- 只在 macOS 上实机验证过；Windows 和 Linux 的路径由测试覆盖。
- 它不会替你改核心文件，只是让编辑器不再为你已做的改动报警。编辑器厂商不支持修改核心文件。
